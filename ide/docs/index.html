JAPPL Documentation

JAPPL is a text language that compiles to Scratch .sb3 projects. This page is the block-by-block conversion reference: each Scratch block is listed with its Scratch meaning, JAPPL form when implemented, and the Scratch 3 opcode emitted by the compiler.

Status: Supported means the current JAPPL compiler emits that Scratch block. Partial means related functionality exists but the exact Scratch block is not fully represented. Not implemented means it is documented here as a Scratch block but the current compiler does not emit it.
Important: this table describes the current compiler, not a promise that every Scratch block already works. Unsupported blocks are intentionally marked instead of pretending they compile.

How conversion works

JAPPL parses your source into an AST and the emitter converts that AST into Scratch block JSON. Literal strings use quotes; an unquoted identifier is a variable expression.

when (green flag)
{
    say ("Hello world") for (2) seconds
    move (10) steps
    set (score) to (0)
}

For example, say ("hello") produces the Scratch looks_say block with a text input, while say (hello) produces a variable reporter input. This distinction is important.

Extensions and non-core blocks

Scratch also has extensions such as Pen, Music, Video Sensing, Text to Speech, Translate, micro:bit, Makey Makey and experimental Scratch Lab features. These are separate from the core Scratch block set and are not currently emitted by the JAPPL compiler.

JAPPL Syntax

Text

Use quotes for literal text.

say ("hello world")

Variables

Use a variable name when you want its value.

set (score) to (10)
say (score)

Blocks with bodies

Use braces for Scratch C-block contents.

repeat (10)
{
    move (10) steps
}

Conditions

if <(score) > (10)>
{
    say ("High score")
}

Costumes

switch costume to (costume1)
next costume

Costume assets are packaged into the generated SB3 by the IDE/compiler pipeline.

Lists

add ("apple") to (fruits)
say (item (1) of (fruits))
Conversion rule: JAPPL is not a textual Scratch clone. The compiler creates real Scratch block JSON, including opcodes, inputs, fields, parent/next links and nested substacks. That is why the generated file opens as an SB3 project rather than merely displaying JAPPL source.

Current conversion priority

  1. Core Motion, Looks, Events, Control, Sensing, Operators, Variables/Lists and My Blocks are documented above.
  2. Rows marked Supported are the current compiler surface.
  3. Rows marked Not implemented are deliberately left visible so the documentation can grow as the compiler gains blocks.
  4. When a block is implemented, its row should be changed from Not implemented to Supported and its exact JAPPL syntax should be added.
